## Best practices

- Tell your members about the new support system and how to open a ticket.
- Set up ping roles and users for ticket notifications in the <DashLink route="?next=/ticket-settings">Ticket Settings</DashLink>.
- Briefly train your staff. The **Managing Support** section is a good reference, especially if they haven't used modmail or Discord bots before.
- Keep the bot's permissions in the ticket forum as they are. The bot manages them.
- Test changes by opening a ticket yourself before you announce them.

## Terminology

| Term         | Description                                                                       |
| ------------ | --------------------------------------------------------------------------------- |
| Ticket\*     | A support conversation between a user and server staff                            |
| Panel        | A message with a button in a server for users to create tickets                   |
| Ticket Forum | A forum channel in a server where tickets are created as threads for server staff |
| Entity       | A general term for "a user or a role" in SupportMail                              |

\* Tickets are in the process of changing. In the future, tickets will be a backend concept for server staff only.
Users will experience support mostly as one continuous thread, rather than managing separate tickets.
