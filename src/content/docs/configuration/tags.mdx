Tags (also called snippets) are reusable pieces of text your staff can send with the `/tag` command. This page covers **creating and managing** them. For how staff send tags, see [Using Tags](/getting-support/using-tags).

## Managing tags

Manage tags in the <DashLink route="?next=/tags">dashboard</DashLink> or with `/config tags` in Discord, which has subcommands for adding, removing and editing tags.

Each tag has:

- **Name** - what staff type to send it (`/tag name-or-id`). Keep it short and memorable.
- **Content** - the text that gets sent. This is what the user (or channel) sees.

## Access control

By default any staff member can send tags. To restrict who can use the `/tag` command - or which channels, roles or users it's allowed in - use <DashLink route="?next=/command-config">Command Config</DashLink>.

To limit **individual tags** to certain roles or channels, or to always send them hidden, use [tag rule sets](/configuration/tag-rule-sets).

You can also stop specific users from using tags entirely by adding them to the **Tags** scope in [Blacklisting](/managing-support/blacklisting).

## Tips

- Create tags for your most common answers (how to open a ticket, working hours, known issues) so replies stay consistent.
- Tags work both inside and outside tickets, so the same snippet can answer a DM or a public channel question.

<Aside type="note">
  Tags are a great pairing with categories - a tag per common topic keeps your
  team's responses fast and uniform.
</Aside>
